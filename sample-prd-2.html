AI 클론 메신저 — 개발 기획 PRD
작성자 송하윤 (PO) 버전 v2.0 · MVP 플랫폼 Web (모바일 대응) 빌드 바이브코딩
STAGE 1 PRD 1페이지
👤 경영자에게
전문가 클론이 팔로워와 24시간 채팅하는 MVP를 만들어, "클론 마스터가 과금할 의향이 있는가"를 검증한다.
⚙️ 개발자에게
클론 프로필·채팅·생성 3개 핵심 화면을 구현하고, RAG 파이프라인(지식 임베딩 → 벡터 검색 → LLM 응답)을 MVP의 기술 핵심으로 완성한다.
📣 마케터에게
팔로워가 특정 전문가 클론과 채팅하는 경험을 통해 "이 전문가의 생각을 직접 듣는 것"을 가치로 전달한다.

✦ 두 여정이 클론 프로필에서 교차 — 팔로워는 소비(채팅), 마스터는 생산(생성·관리). 이 교차점이 서비스의 핵심 인터페이스
2 화면 목록 — 각 화면의 목적과 핵심 컴포넌트 실제 서비스 화면 기준
화면 이름 사용자 목적 핵심 컴포넌트 대상
S1 홈 피드 원하는 전문가를 찾고 클론 프로필로 이동한다 검색바(이름·질문), 추천 클론 리스트(아바타·이름·직함·대표 질문 1줄) 팔로워
S2 클론 프로필 이 클론이 어떤 전문가인지 파악하고 채팅 진입을 결정한다 프로필 사진·이름·AI 뱃지, 소개 텍스트, 경력 태그, 외부 링크 뱃지, 추천 질문 칩 3개, 채팅하기 CTA 팔로워
S3 채팅 클론에게 질문하고 전문가의 관점이 담긴 답변을 받는다 클론 인사 메시지(자동), 추천 질문 칩(초기), 메시지 버블(user/clone), 텍스트 입력창, 파일 첨부, 전송 버튼 팔로워
S4 마이페이지 클론 생성으로 진입하거나 내 클론을 관리한다 클론 미생성 상태: 생성 CTA / 생성 후: 내 클론 링크, 계정 정보, 로그아웃 마스터
S5 클론 생성 질문에 답하는 방식으로 내 AI 클론의 기초 지식을 구성한다 단계별 온보딩 질문, 전문 분야·이력 입력, 콘텐츠 URL 연결, 추천 질문 설정, 프로필 이미지 업로드 마스터
S6 관리 콘솔 팔로워 질문에 대한 클론 답변을 검토하고 품질을 개선한다 질문 목록, 미응답 모아보기, 답변 수정 인터페이스, 지식 추가/수정 MVP 다음 버전 마스터
✦ S1~S3(팔로워·읽기)과 S4~S5(마스터·쓰기)를 MVP 우선 완성. S6(관리 콘솔)은 가정 검증 후 추가
3 데이터 구조 — 흐름 이해 → 객체 관계 → 설계 결정 기술 핵심
① 데이터 흐름 — 질문이 들어와서 답변이 나오기까지
① 지식 학습 (사전)
클론 마스터가 URL을 입력하면 콘텐츠를 크롤링해 텍스트를 추출한다. 추출된 텍스트는 임베딩 모델을 통해 벡터로 변환되어 DB에 저장된다.
Input: URL → Crawl → Chunk → Embed → Knowledge DB
→
② 질문 수신 (실시간)
팔로워가 질문을 입력하면, 이 질문도 벡터로 변환된다. 변환된 벡터로 Knowledge DB에서 가장 유사한 지식 덩어리를 검색한다. (벡터 유사도 검색)
Input: 질문 → Embed → Vector Search → Top-K 지식 반환
→
③ 응답 생성 (RAG)
검색된 지식 + 클론 페르소나 + 팔로워 질문을 LLM 프롬프트에 함께 주입한다. LLM이 "이 전문가라면 이렇게 답할 것"처럼 응답을 생성한다.
Prompt = 지식 + 페르소나 + 질문 → LLM → 응답 + 출처 URL
※ ①은 마스터가 클론을 설정할 때 1회 실행. ②③은 팔로워가 채팅할 때마다 실시간 실행.

③ 핵심 설계 결정 — 바이브코딩 전 결정해야 하는 3가지
🗄️ 벡터 DB 선택
무엇을 결정하나 Knowledge.embedding 저장 및 유사도 검색 방식

간단 PostgreSQL + pgvector 확장 — 별도 인프라 불필요
확장 Pinecone / Weaviate — 대용량에 유리
⚠ MVP는 pgvector 권장
🔐 인증 방식
무엇을 결정하나 ChatSession.user_id = null 허용 여부와 세션 유지 방식

팔로워: 비로그인 허용 — 익명 세션 ID 쿠키로 관리
마스터: 로그인 필수 — 클론 생성·수정 권한
⚠ 비로그인 세션은 브라우저 닫으면 소멸
⚡ 크롤링 처리 방식
무엇을 결정하나 URL 입력 후 임베딩 완료까지 사용자 대기 방식

동기 즉시 처리 — 구현 쉽지만 타임아웃 위험
비동기 큐 처리 — "학습 중" 상태 표시 필요
⚠ MVP는 비동기 + 상태 표시 권장
✦ 데이터 흐름 ①②③을 이해하면 ERD의 각 테이블이 왜 존재하는지 설명할 수 있다 — 이것이 PO가 개발자에게 설명하는 방식
4 핵심 API — MVP 구현 범위 우선순위 포함 개발자 기준
엔드포인트 기능 인증 연결 화면 우선순위
GET/clones 클론 목록 조회 (추천 순, 검색 쿼리 포함) 불필요 S1 P0
GET/clones/:slug 클론 프로필 + 추천 질문 조회 불필요 S2 P0
POST/sessions 채팅 세션 생성 (비로그인 허용, user_id nullable) 선택 S3 P0
POST/sessions/:id/messages 메시지 전송 → RAG 검색 → LLM 응답 생성 반환 선택 S3 P0 ★핵심
POST/clones 클론 생성 (온보딩 입력값 → Clone 레코드 생성) 필수 S5 P1
POST/clones/:id/knowledge URL 크롤링 → 텍스트 추출 → 임베딩 저장 (비동기) 필수 S5 P1
GET/sessions/:id/messages 대화 이력 조회 (세션 재개 시 이력 복원) 선택 S3 P2
PUT/clones/:id/knowledge/:kid 지식 수정 (클론 마스터 파인튜닝) 필수 S6 P2
P0 = MVP 필수 / P1 = MVP 포함 / P2 = 다음 버전  ·  ★ POST /messages가 RAG 파이프라인 전체를 포함하는 가장 복잡한 API
✦ P0 4개 API가 작동하면 "팔로워가 클론과 채팅하는" 핵심 가치 검증 가능 — P0 완성 후 P1 진행 권장

6 핵심 가정 & 검증 방법 — 비즈니스 가정 / 기술 가정 구분 방법론 핵심
A
클론 마스터는 팔로워 인게이지먼트를 위해 기꺼이 비용을 낼 것이다
비즈니스 가정
가정 내용
인플루언서·코치·컨설턴트는 팔로워 응대와 유료 전환에 돈을 쓴다. 클로라 클론이 그 역할을 하면, 사용자 과금이 아닌 클론 마스터 과금이 수익 모델이 된다.
검증 방법
무료 클론 마스터 30명 운영 → 유료 전환 의향 인터뷰. 컨설팅 퍼널 연결 사례 수집 (클론 상담 → 유료 1:1 전환).
성공 지표
유료 전환 의향 20% 이상 / 클론을 통한 유료 컨설팅 연결 월 3건 이상
B
RAG 응답이 "이 전문가의 답변"처럼 느껴질 만큼 차별화된다
기술 가정
가정 내용
전문가 콘텐츠 기반 RAG가 범용 LLM과 구분될 만큼 해당 전문가의 어조·관점을 반영해야 한다. 그렇지 않으면 재방문이 없다.
검증 방법
동일 질문 → 클론 vs ChatGPT 블라인드 테스트. 5인 사용자가 어느 쪽이 더 "해당 전문가답다"고 느끼는지 비교.
성공 지표
블라인드 테스트 5인 중 4인 이상 클론 선택 / 채팅 재방문율 50% 이상
✦ 가정 A(비즈니스)는 MVP 배포 후 2주 내 인터뷰로 검증. 가정 B(기술)는 배포 전 내부 테스트로 먼저 확인 — B 미통과 시 배포 보류
