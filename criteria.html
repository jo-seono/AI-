AI 솔로프러너 육성 프로그램 · Stage 2(사전교육)

MVP 스테이지
산출물 요구사항

창업방법론(고객 → 문제 → 솔루션)이 반영된 MVP를 만들기 위한 3가지 제출물 기준

1 랜딩페이지 → 2 PRD 1페이지 → 3 MVP URL
제출물 1

서비스 소개 랜딩페이지

① 고객과 문제 정의 — 누구의, 어떤 문제인가
타깃 고객 페르소나 — 직업·상황·행동 패턴이 1~2문장으로 명확히 서술돼야 함
핵심 불편 상황 (Pain Scene) — "언제, 무엇 때문에 힘든가"를 구체적 시나리오로 서술 (숫자·빈도·감정 포함)
기존 대안의 한계 — 고객이 지금 어떻게 해결하고 있고, 왜 그게 불충분한지 1~2줄
검증 기준 — "고객이 직접 한 말처럼 읽히는가?" 추상적인 니즈 나열이 아닌, 특정 상황의 실제 불편함이 담겨야 합니다.
② 솔루션과 가치 — 어떻게 해결하고, 고객에게 무엇이 달라지는가
핵심 기능 2~3개 — 기능 나열이 아닌, 각 기능이 위에서 정의한 어떤 Pain을 해결하는지 연결해서 서술
Before / After 고객 경험 — 솔루션 사용 전·후 고객의 상황이 어떻게 달라지는지 대비 구조로 표현
핵심 가치 문장 1개 — "누구를 위한, 무엇을 하는, 왜 다른" 구조의 한 문장 포지셔닝
검증 기준 — 기능 설명과 Pain 정의가 1:1로 연결되는가? "좋은 기능"이 아니라 "이 고객의 이 문제를 푸는 기능"으로 읽혀야 합니다.
③ 신뢰 요소 — 실제로 만들고 검증했다는 근거
MVP 링크 삽입 — 랜딩페이지 내 실제 작동하는 MVP URL CTA 버튼 포함
고객 인터뷰 또는 반응 1건 이상 — 실제 타깃 고객에게 보여주고 받은 피드백 인용 (익명 가능)

2 화면 목록 — 각 화면의 목적과 핵심 컴포넌트 실제 서비스 화면 기준
요구사항
화면 ID (S1~Sn) — 각 화면에 고유 번호를 부여해 유저 플로우(블록 1)와 연결
사용자 목적 — "이 화면에서 사용자가 무엇을 하려는가"를 1줄 동사형 문장으로 서술
핵심 컴포넌트 — 화면을 구성하는 UI 요소를 콤마로 나열 (완전한 스펙이 아니어도 됨)
작성 예시 — Clora.co 기준
화면이름사용자 목적핵심 컴포넌트대상
S1 홈 피드 원하는 전문가를 찾고 클론 프로필로 이동한다 검색바(이름·질문), 추천 클론 리스트(아바타·이름·직함·대표 질문 1줄) 팔로워
S2 클론 프로필 이 클론이 어떤 전문가인지 파악하고 채팅 진입을 결정한다 프로필 사진·이름·AI 뱃지, 소개 텍스트, 경력 태그, 추천 질문 칩 3개, 채팅하기 CTA 팔로워
S3 채팅 클론에게 질문하고 전문가 관점의 답변을 받는다 클론 인사 메시지(자동), 추천 질문 칩(초기), 메시지 버블, 텍스트 입력창, 전송 버튼 팔로워
S4 마이페이지 클론 생성으로 진입하거나 내 클론을 관리한다 클론 미생성: 생성 CTA / 생성 후: 내 클론 링크, 계정 정보, 로그아웃 마스터
S5 클론 생성 질문에 답하는 방식으로 내 AI 클론의 기초 지식을 구성한다 단계별 온보딩 질문, 전문 분야·이력 입력, 콘텐츠 URL 연결, 추천 질문 설정 마스터
S6 관리 콘솔 팔로워 질문에 대한 클론 답변을 검토하고 품질을 개선한다 질문 목록, 미응답 모아보기, 답변 수정 인터페이스 MVP 다음 버전 마스터
✦ 화면 ID가 블록 1 유저 플로우의 화면과 일치해야 함 — S번호로 두 블록이 연결됨
3 MVP 범위 — 판단 기준 포함 → MVP URL 연결
요구사항
In (MVP 구현) — 이번 MVP에서 반드시 작동해야 하는 기능과 화면, 각 항목마다 "왜 In인가"의 판단 근거 1줄
Out (다음 버전) — 의도적으로 제외한 기능과 그 이유. "가정 검증 후" 조건을 명시할 것
MVP 완료 판단 기준 — 외부인이 URL 하나로 접속해 설명서 없이 핵심 가치를 경험할 수 있는 조건을 1~2줄로 명시

MVP 완료 판단 기준 — 팔로워가 URL 하나로 진입해 30초 내에 클론과 채팅할 수 있고, 클론 마스터가 URL 3개 입력만으로 자신의 클론을 만들 수 있으면 MVP 완성.
✦ In/Out은 기능 우선순위가 아니라 검증 순서의 문제 — Out 항목에는 반드시 "가정 검증 후" 조건을 명시할 것
4 핵심 가정 & 검증 방법 — 비즈니스 가정 / 기술 가정 구분 방법론 핵심
요구사항
가정 1~2개 — "이게 틀리면 이 프로덕트는 의미없다"는 전제. 비즈니스 가정(수익·고객행동)과 기술 가정(구현가능성·품질)을 구분해 작성
검증 방법 — MVP를 통해 이 가정을 어떻게 확인할 것인지 (인터뷰·테스트·데이터 기준)
성공 지표 — "이 수치가 나오면 가정이 맞다"는 구체적 숫자 또는 조건
작성 예시 — Clora.co 기준
A
클론 마스터는 팔로워 인게이지먼트를 위해 기꺼이 비용을 낼 것이다
비즈니스 가정
가정 내용
인플루언서·코치·컨설턴트는 팔로워 응대와 유료 전환에 돈을 쓴다. 사용자 과금이 아닌 클론 마스터 과금이 수익 모델이 된다.
검증 방법
무료 클론 마스터 30명 운영 → 유료 전환 의향 인터뷰. 컨설팅 퍼널 연결 사례 수집.
성공 지표
유료 전환 의향 20% 이상 / 유료 컨설팅 연결 월 3건 이상
B
RAG 응답이 "이 전문가의 답변"처럼 느껴질 만큼 차별화된다

가정 내용
전문가 콘텐츠 기반 RAG가 범용 LLM과 구분될 만큼 해당 전문가의 어조·관점을 반영해야 한다.

동일 질문 → 클론 vs ChatGPT 블라인드 테스트. 5인 사용자 비교 평가.

제출물 3

MVP IT 솔루션 (바이브코딩) URL

① 작동 요건 — 실제로 작동해야 하는 핵심 기능
핵심 기능 1개 완성 — 랜딩페이지에서 정의한 Pain을 해결하는 기능이 외부인도 URL만으로 실행 가능해야 함
회원가입 없이 체험 가능한 데모 플로우 — 로그인 없이도 핵심 가치를 30초 내에 경험할 수 있어야 함
모바일 접근 가능 — 스마트폰 브라우저에서 주요 기능이 깨지지 않아야 함
검증 기준 — 평가자가 URL을 열었을 때 설명서 없이 핵심 기능을 사용해볼 수 있는가?
② 방법론 연결 — MVP가 PRD 정의와 일치하는가
랜딩페이지의 핵심 기능 정의와 MVP 구현이 일치 — "설명한 기능"이 실제로 작동해야 함 (범위 불일치 시 이유 서술)
타깃 고객이 사용자로 상정된 UX — 인터페이스의 언어·용어·플로우가 정의한 페르소나 기준으로 설계됐는지
탈락 기준
